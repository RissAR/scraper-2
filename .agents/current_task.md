# ТЕХНІЧНЕ ЗАВДАННЯ: Комплексна оптимізація стабільності, відмовостійкості (Resilience) та авто-моніторингу парсерів

## 1. Мета та огляд
Підготувати бота до повністю автономної роботи 24/7 перед фінальним деплоєм на Ubuntu Server:
1. Забезпечити гарантовану доставку нових квартир від власників навіть у разі збоїв вилучення номера телефону (Graceful Degradation).
2. Запобігти банам IP/акаунтів через автоматичний запобіжник Circuit Breaker та ротацію проксі при 429/403.
3. Додати систему авто-сповіщень адміністратора про технічні збої та ліміти прямо в Telegram.
4. Захистити пам'ять сервера від витоків та підвислих процесів Playwright (Watchdog).
5. Надати можливість адміну оперативно оновлювати сесійні cookies без перезапуску контейнера.

## 2. Детальні вимоги до реалізації (5 модулів оптимізації)

### Модуль 1. Плавна деградація (Graceful Degradation)
* **Проблема:** Якщо Playwright не зміг розкрити кнопку телефону (таймаут, зміна верстки або мікро-збій), оголошення не повинно втрачатися. Знайдений об'єкт від власника — найвища цінність.
* **Реалізація:**
  - У `olx_scraper.py` та `dimria_scraper.py`: якщо виклик Playwright завершився таймаутом або повернув `None`, об'єкт **НЕ відхиляється**.
  - `item.phone` залишається `None` (або `item.phone = "Переглянути на сайті / у додатку"`).
  - У повідомленні Telegram виводиться:
    `📞 Телефон: Не розкрито автоматично (перегляньте за посиланням нижче)`.
  - Об'єкт позначається в базі даних як знайдений, щоб уникнути повторного спаму.

### Модуль 2. Circuit Breaker та Експоненційний Backoff
* **Проблема:** Якщо OLX або DIM.RIA повертають `429 Too Many Requests` або `403 Forbidden`, продовження частих запитів призведе до постійного бана IP.
* **Реалізація:**
  - Створити лічильник послідовних критичних помилок для кожного скрапера (`consecutive_errors: int = 0`).
  - Якщо отримано 429/403 або помилку з'єднання:
    1. Автоматично взяти наступний активний проксі з бази даних (`database.get_active_proxies()`).
    2. Якщо проксі відсутні або вичерпані: скрапер тимчасово переходить у режим «Cooldown» (пауза 10–15 хвилин замість стандартного інтервалу).
  - При першому ж успішному запиті лічильник помилок скидається на 0.

### Модуль 3. Auto-Alerts для Адміністратора в Telegram
* **Реалізація:**
  - Додати функцію `notify_admins(bot: Bot, message: str)` у `bot.py`.
  - Якщо будь-який скрапер зафіксував 3 критичні помилки поспіль (HTTP 429/403, масові таймаути чи краш браузера):
    * Бот автоматично надсилає адмінам (`ADMIN_IDS`) повідомлення:
      `⚠️ УВАГА: Скрапер {OLX/DIM.RIA} зафіксував 3 збої поспіль! Помилка: {короткий опис}. Скрапер тимчасово призупинено на 15 хв.`
    * Після успішного відновлення роботи надіслати:
      `✅ РОБОТУ ВІДНОВЛЕНО: Скрапер {OLX/DIM.RIA} знову успішно отримує дані.`

### Модуль 4. Watchdog & Управління пам'яттю Playwright
* **Проблема:** Завислі headless-процеси Chromium можуть накопичуватися та переповнювати оперативну пам'ять на сервері.
* **Реалізація:**
  - Кожен виклик Playwright огортати в жорсткий таймаут: `asyncio.wait_for(extractor_coroutine, timeout=25.0)`.
  - Обов'язковий блок `try...finally`:
    ```python
    finally:
        if page and not page.is_closed():
            await page.close()
        if context:
            await context.close()
        if browser:
            await browser.close()
    ```
  - Переконатися, що браузер не залишає фонових зомбі-процесів при таймаутах.

### Модуль 5. Гаряче оновлення сесійних даних (Hot-Reload Cookies)
* **Реалізація:**
  - У меню адміністратора (або команді `/set_cookies`) надати можливість передати нові cookies у форматі тексту `name=val; name2=val2`.
  - Зберігати оновлені cookies у базі даних SQLite (`bot_state` або `settings_store`), щоб вони підтягувалися на льоту без необхідності перезапускати процес чи редагувати `.env` на сервері.

## 3. Критерії приймання та верифікація (Verification)
1. Синтаксична перевірка: `python3 -m py_compile bot.py olx_scraper.py dimria_scraper.py database.py config.py`.
2. Тест стійкості: імітація відсутності номера телефону — картка успішно формується та надсилається в Telegram без помилок чи падіння фонового циклу.
3. Сповіщення адміна: при ручній симуляції помилки бот коректно відправляє алерт в особисті повідомлення адміна (`123456789`).
4. Пам'ять: відсутність завислих процесів `chromium` після завершення прогону парсерів.

# ТЕХНІЧНЕ ЗАВДАННЯ: Роздільне керування парсерами (OLX / DIM.RIA / ВСІ) та Дворівнева система безпеки (Кабінет Адміна / Кабінет Ріелтора)

## 1. Мета та огляд
1. **Роздільне керування парсерами:**
   * Створити незалежне керування для тестового та робочого запуску:
     - Окремий Старт/Стоп для **OLX.ua**.
     - Окремий Старт/Стоп для **DIM.RIA**.
     - Єдиний перемикач **Запустити ВСІ / Зупинити ВСІ**.
     - Кнопки разового тестування (1 тестове коло): **«🔍 Тест OLX»** та **«🔍 Тест DIM.RIA»** для миттєвої перевірки працездатності без очікування інтервалу таймера.
2. **Дворівнева система доступу та безпеки (RBAC):**
   * **Кабінет Адміністратора:** повний інженерний контроль (керування парсерами, проксі, користувачами, експорт бази).
   * **Кабінет Ріелтора:** чистий робочий інтерфейс для клієнта (тільки потік перевірених квартир від власників, перегляд карток, контакти підтримки).
   * **Захист від сторонніх:** неавторизовані користувачі не мають доступу до функціоналу бота без схвалення адміністратора.

---

## 2. Архітектурні вимоги до реалізації

### Крок 1. База даних (`database.py`)
1. **Збереження стану парсерів:**
   * У таблиці `bot_state` (або `settings`) зберігати два незалежні прапорці:
     - `is_olx_active INTEGER DEFAULT 1`
     - `is_dimria_active INTEGER DEFAULT 1`
   * Додати методи:
     - `get_parsers_state() -> dict[str, bool]`
     - `set_parser_state(parser_name: str, is_active: bool)`
     - `set_all_parsers_state(is_active: bool)`
2. **Таблиця користувачів з ролями (`users`):**
   * Створити таблицю `users` (або мігрувати `subscribers`):
     ```sql
     CREATE TABLE IF NOT EXISTS users (
         telegram_id INTEGER PRIMARY KEY,
         username TEXT,
         full_name TEXT,
         role TEXT NOT NULL DEFAULT 'realtor', -- 'admin', 'realtor', 'pending'
         is_active INTEGER NOT NULL DEFAULT 1,
         created_at TEXT NOT NULL
     );
     ```
   * Методи:
     - `get_user_role(telegram_id: int) -> Optional[str]`
     - `add_user(telegram_id: int, username: str, full_name: str, role: str = 'realtor')`
     - `list_users() -> list[dict]`
     - `set_user_status(telegram_id: int, is_active: bool)`

### Крок 2. Конфігурація (`config.py`)
* Додати параметр `ADMIN_IDS: str = ""` (список Telegram ID адміністраторів через кому).
* Додати метод/властивість `settings.admin_id_list -> list[int]`. Якщо `telegram_id` є в `ADMIN_IDS`, він автоматично отримує роль `admin`.

### Крок 3. Інтерфейс та інлайн-клавіатури (`keyboards.py`)
1. **`admin_main_keyboard(is_olx: bool, is_dimria: bool)`:**
   * Рядок 1:
     - `[🟢 OLX: Зупинити]` (якщо активний) / `[🔴 OLX: Запустити]` (якщо вимкнено).
     - `[🟢 DIM.RIA: Зупинити]` / `[🔴 DIM.RIA: Запустити]`.
   * Рядок 2:
     - `[🚀 Запустити ВСІ]` (якщо хоч один вимкнено) або `[⏸ Зупинити ВСІ]`.
   * Рядок 3:
     - `[🔍 Тест OLX (1 коло)]` | `[🔍 Тест DIM.RIA (1 коло)]`.
   * Рядок 4:
     - `[📦 Об'єкти в базі]` | `[📊 Експорт в Excel]`.
   * Рядок 5:
     - `[👥 Користувачі]` | `[🌐 Меню проксі]`.
2. **`realtor_main_keyboard()`:**
   * Простий клієнтський інтерфейс:
     - `[📦 Переглянути останні квартири]`
     - `[ℹ️ Мій статус та підтримка]`
3. **`unauthorized_keyboard(user_id: int)`:**
   * `[📩 Надіслати запит на доступ]` (надсилає сповіщення адміну).

### Крок 4. Логіка обробки в `bot.py`
1. **Фільтрація за ролями на `/start`:**
   * Якщо користувач у `settings.admin_id_list` або має роль `'admin'` ➡️ відкривається **Кабінет Адміністратора**.
   * Якщо користувач має роль `'realtor'` та `is_active == 1` ➡️ відкривається **Кабінет Ріелтора**.
   * Якщо новий/сторонній користувач ➡️ заглушка: *"🔒 Доступ закрито. Зверніться до адміністратора"* + кнопка подачі заявки.
2. **Обробники перемикання парсерів (Callback Handlers):**
   * `toggle_olx`: перемикає стан OLX, оновлює текст повідомлення та кнопки.
   * `toggle_dimria`: перемикає стан DIM.RIA, оновлює інтерфейс.
   * `toggle_all`: вмикає або вимикає обидва скрапери.
   * `test_olx_now`: виконує 1 разовий запуск `olx_scraper.fetch_listings()`, формує звіт у чат адміна.
   * `test_dimria_now`: виконує 1 разовий запуск `dimria_scraper.fetch_new_listings()`, формує звіт у чат адміна.
3. **Ізоляція у фоновому циклі моніторингу:**
   * Перед кожним колом фоновий воркер перевіряє:
     - Якщо `is_olx_active` ➡️ скануємо OLX.
     - Якщо `is_dimria_active` ➡️ скануємо DIM.RIA.
     - Якщо обидва вимкнено ➡️ просто чекаємо інтервал без мережевих запитів.

---

## 3. Критерії приймання та верифікація (Verification)
1. Синтаксична валідація: `python3 -m py_compile bot.py keyboards.py database.py config.py`.
2. Натискання кнопки `[🔴 DIM.RIA: Запустити]` перемикає тільки стан DIM.RIA на зелений.
3. Натискання `[🔍 Тест DIM.RIA]` здійснює тестовий запит до `searchEngine/v2` і повертає коротке резюме в чат.
4. Звичайний ріелтор без прав адміна не має доступу до кнопок перемикання парсерів чи меню проксі.

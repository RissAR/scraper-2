# 🏢 RieltorBot — Автономна система моніторингу нерухомості від власників (OLX.ua & DIM.RIA)

Потужний асинхронний Telegram-бот для моніторингу нових оголошень про довгострокову оренду 1-кімнатних квартир у м. Дніпро в режимі реального часу (інтервал 2–4 хвилини) **виключно від прямих власників** з автоматичним відсіканням посередників та ріелторів.

---

## 🌟 Ключові можливості та архітектура

### 1. Подвійний скрапінг у реальному часі (Dual-Source Engine)
- **OLX.ua API & On-Demand Playwright:**
  - Швидке отримання свіжих пропозицій через офіційний JSON API OLX з параметром `owner_type=private`.
  - Збагачення даними: поверх, поверховість, загальна площа, площа кухні, дата публікації, фотографії високої якості.
  - On-Demand headless Chromium (Playwright) з блокуванням зайвих медіа-ресурсів для розкриття захищених номерів телефонів власників, обходу Cloudflare/Friction SDK та взаємодії з DOM.
- **DIM.RIA (dom.ria.com) Scraper:**
  - Попередній пошук кандидатів через `searchEngine/v2` з обов'язковим серверним фільтром «Від власника» (`1437_1436`).
  - Попередня дедуплікація в пам'яті та базі даних SQLite до запуску браузера для максимальної економії ресурсів CPU/RAM.
  - On-Demand вилучення повних характеристик, описів та перехоплення телефонних номерів власників через Playwright.

### 2. Багаторівневий анти-ріелтор фільтр (Anti-Realtor Shield)
- **Рівень 1 (Тип профілю):** Відсікання акаунтів типу `business` / `agency` / комерційних посередників.
- **Рівень 2 (Семантичний аналіз):** Жорсткий список стоп-слів («комісія», «агентство», «АН», «рієлтор», «послуги ріелтора», «колегам не турбувати», «співпрацюю» тощо) з інтелектуальним урахуванням контексту (наприклад, фрази «без комісії» або «без ріелторів» не блокуються).
- **Рівень 3 (Ліміт активних оголошень):** Перевірка кількості активних оголошень автора (`author_ads_count <= 2`). Якщо в акаунта більше 2 активних оголошень — це прихований ріелтор або посередник, об'єкт автоматично відхиляється.
- **Рівень 4 (Фільтр віку оголошення):** Захист від старих оголошень, штучно піднятих у ТОП (`MAX_AD_AGE_HOURS=48`).

### 3. Дворівнева рольова модель (Two-Tier RBAC) та Безпека
- **Кабінет Адміністратора (`role = admin`):**
  - Роздільне керування парсерами: запуск/зупинка OLX.ua та DIM.RIA окремо або одночасно (`🟢 OLX`, `🟢 DIM.RIA`, `⏸ Зупинити ВСІ` / `🚀 Запустити ВСІ`).
  - Разові діагностичні тести в 1 клік (`🔍 Тест OLX (1 коло)`, `🔍 Тест DIM.RIA (1 коло)`).
  - Керування користувачами: перегляд списку користувачів, миттєве схвалення/відхилення заявок на доступ, блокування/активація акаунтів, призначення нових адміністраторів.
  - Менеджер проксі: додавання, видалення, автоматичне тестування працездатності та пінгу (`ms`) через запити до OLX.
  - Hot-Reload сесійних Cookies OLX: гаряче оновлення або очищення cookies прямо з інтерфейсу бота (або командою `/set_cookies`) без перезапуску контейнера.
  - Експорт в Excel: генерація та миттєве завантаження повної бази знайдених об'єктів у форматі `.xlsx`.
  - Системний статус: детальний звіт про стан парсерів, Circuit Breaker, проксі, статистику бази даних та активних підписників.
- **Кабінет Ріелтора (`role = realtor`):**
  - Чистий клієнтський інтерфейс: перегляд збережених перевірених квартир із бази зі зручною пагінацією без засмічення чату.
  - Миттєві сповіщення про появу нових квартир від власників із кнопкою `📋 Показати об'єкти` для вивантаження карток стрічкою.
  - Перегляд власного статусу доступу та довідки.
- **Неавторизовані користувачі (`pending` / `rejected`):**
  - Повне блокування доступу як на рівні команд, так і на рівні всіх інлайн-кнопок (`callback_query` RBAC enforcement).
  - Можливість подати заявку на доступ (`📩 Надіслати запит на доступ`), яка миттєво надходить адміністраторам із кнопками `✅ Схвалити` / `❌ Відхилити`.

### 4. Надійність, Конкурентність та Production-захист
- **SQLite WAL Mode & Concurrency:** База даних працює в режимі `PRAGMA journal_mode = WAL;` із `PRAGMA busy_timeout = 5000;`, що повністю виключає помилки `database is locked` під час одночасної роботи двох скраперів та запитів користувачів.
- **Zero Hardcoded Secrets:** Жодних токенів, паролів чи персональних ID у вихідному коді — вся чутлива конфігурація завантажується виключно із захищеного файлу `.env`.
- **Захист від збоїв HTML-розмітки (`html.escape`):** Усі зовнішні дані з оголошень (заголовки, описи, райони, імена авторів, URL, параметри) проходять суворе екранування спецсимволів (`<`, `>`, `&`, `"`), що унеможливлює помилки `TelegramBadRequest`.
- **Маскування облікових даних проксі (`mask_proxy`):** Паролі проксі-серверів (`http://***:***@ip:port`) автоматично маскуються у всіх логах та повідомленнях інтерфейсу.
- **Circuit Breaker & Auto-Alerts:** При 3 послідовних критичних помилках скрапер автоматично переходить у режим `Cooldown` (15 хвилин паузи) та надсилає тривожне сповіщення адміністраторам, а після успішного циклу — повідомляє про відновлення роботи.
- **Watchdog & Graceful Shutdown:** Жорсткий таймаут `25s` на кожну браузерну сесію Playwright з гарантованим закриттям контекстів у блоках `finally` та коректна обробка сигналів `SIGINT`/`SIGTERM` при зупинці Docker-контейнера.

## 📁 Структура проекту

```text
RieltorBot/
├── bot.py                        # Точка входу: aiogram бот, RBAC, інлайн-меню, фоновий сканер, Circuit Breaker
├── keyboards.py                  # Інлайн-клавіатури для Адміністратора, Ріелтора, пагінації, проксі та cookies
├── olx_scraper.py                # Асинхронний скрапер OLX.ua (JSON API + On-Demand Playwright)
├── dimria_scraper.py             # Асинхронний скрапер DIM.RIA (searchEngine/v2 + On-Demand Playwright)
├── database.py                   # Асинхронний менеджер SQLite (WAL mode): оголошення, RBAC, проксі, налаштування
├── proxy_checker.py              # Діагностика доступності та швидкості відгуку проксі-серверів
├── exporter.py                   # Експорт бази даних оголошень у відформатований файл Excel (.xlsx)
├── models.py                     # Pydantic моделі даних (ListingItem)
├── config.py                     # Типізована конфігурація Pydantic Settings (.env)
├── test_olx.py                   # Автономний інтеграційний тест скрапера OLX та дедуплікації БД
├── test_dimria.py                # Автономний інтеграційний тест скрапера DIM.RIA
├── tests/
│   └── test_rbac_and_controls.py # Модульні тести RBAC, станів парсерів та клавіатур
├── requirements.txt              # Залежності Python
├── Dockerfile                    # Production Docker-образ з Playwright Chromium та TZ=Europe/Kyiv
├── docker-compose.yml            # Оркестрація контейнера з авто-перезапуском, томами та ротацією логів
├── .env.example                  # Безпечний шаблон змінних оточення
└── data/                         # Директорія збереження SQLite БД (rieltor_bot.db) та логів (bot.log)
```

## ⚙️ Конфігурація (`.env`)

Усі налаштування та секрети підтягуються **виключно з файлу `.env`** (файл `.env` додано до `.gitignore` та `.dockerignore`).

Створіть файл `.env` на основі шаблону:

```bash
cp .env.example .env
```

| Параметр | Опис | Приклад значення |
|---|---|---|
| `BOT_TOKEN` | API токен Telegram-бота від `@BotFather` (**обов'язково**) | `YOUR_BOT_TOKEN_HERE` |
| `ADMIN_IDS` | Список Telegram ID адміністраторів через кому | `123456789,987654321` |
| `TELEGRAM_CHAT_ID` | Опціональний ID каналу/чату для дублювання стрічки | *(порожньо або ID чату)* |
| `POLL_INTERVAL_SECONDS` | Інтервал автоматичного сканування в секундах (2–4 хв) | `180` |
| `CITY_NAME` | Назва міста для відображення та фільтрації | `Дніпро` |
| `CITY_ID` | ID міста в системі OLX (Дніпро = `121`) | `121` |
| `CATEGORY_ID` | ID категорії OLX (`1760` = довгострокова оренда квартир) | `1760` |
| `MIN_PRICE` | Мінімальна ціна оренди в грн (опціонально) | `3000` |
| `MAX_PRICE` | Максимальна ціна оренди в грн (опціонально) | `25000` |
| `EXCLUDED_DISTRICTS` | Райони міста для виключення через кому | *(порожньо або список районів)* |
| `ONLY_OWNERS` | Жорстка фільтрація виключно власників | `true` |
| `MAX_OWNER_ACTIVE_ADS` | Максимум активних оголошень в автора для визнання власником | `2` |
| `MAX_AD_AGE_HOURS` | Максимальний вік оголошення в годинах (захист від ТОП-підняттів) | `48` |
| `INIT_MARK_AS_SEEN` | Позначати поточні оголошення баченими при першому запуску на чистій БД | `true` |
| `DIMRIA_ENABLED` | Увімкнення моніторингу DIM.RIA (`dom.ria.com`) | `true` |
| `DIMRIA_STATE_ID` | ID області в системі DIM.RIA (Дніпропетровська = `11`) | `11` |
| `DIMRIA_CITY_ID` | ID міста в системі DIM.RIA (Дніпро = `11`) | `11` |
| `OLX_BEARER_TOKEN` | Опціональний Bearer-токен OLX | *(порожньо)* |
| `OLX_COOKIES` | Початкові сесійні cookies OLX (можна оновлювати через меню бота) | `name=val; name2=val2` |
| `PROXY_URL` | Базовий проксі за замовчуванням (опціонально) | `http://user:pass@ip:port` |
| `DB_PATH` | Шлях до файлу бази даних SQLite | `data/rieltor_bot.db` |

## 🚀 Розгортання та запуск

### Варіант 1. Production-деплой через Docker Compose (Ubuntu Server)

```bash
# 1. Клонувати репозиторій
git clone https://github.com/RissAR/scraper-2.git
cd scraper-2

# 2. Створити та заповнити .env файл (вказати BOT_TOKEN та ADMIN_IDS)
cp .env.example .env
nano .env

# 3. Запустити контейнер у фоновому режимі зі збіркою образу
docker compose up -d --build

# 4. Перевірити логи роботи бота
docker compose logs -f
```

**Особливості Docker-конфігурації:**
- Автоматичне встановлення Chromium та всіх системних бібліотек (`playwright install chromium --with-deps`).
- Часова зона `TZ=Europe/Kyiv`.
- Збереження бази даних `data/rieltor_bot.db` та логів `data/bot.log` на хост-машині через volume `./data:/app/data`.
- Політика `restart: unless-stopped` та автоматична ротація логів (`max-size: "10m"`, `max-file: "3"`).

---

### Варіант 2. Локальний запуск (Linux / Розробка)

```bash
# 1. Створити та активувати віртуальне середовище
python3 -m venv .venv
source .venv/bin/activate

# 2. Встановити залежності Python
pip install -r requirements.txt

# 3. Встановити браузер Chromium для Playwright
playwright install chromium --with-deps

# 4. Налаштувати .env
cp .env.example .env
nano .env

# 5. Запустити тести (опціонально)
python -m py_compile bot.py config.py database.py olx_scraper.py dimria_scraper.py keyboards.py
python tests/test_rbac_and_controls.py

# 6. Запустити бота
python bot.py
```

## 🤖 Команди та інтерактивне управління

Усе основне керування реалізовано через **інлайн-кнопки** в Telegram-інтерфейсі:

| Команда / Дія | Опис | Рівень доступу |
|---|---|---|
| `/start` | Ініціалізація профілю, відкриття панелі Адміністратора, Кабінету Ріелтора або форми запиту доступу | Усі користувачі |
| `/menu` | Швидкий виклик головного меню відповідно до ролі | Авторизовані (`admin`, `realtor`) |
| `/set_cookies [рядок]` | Швидке гаряче оновлення сесійних cookies OLX у SQLite без перезапуску бота | Тільки Адміністратор |
| `🟢 OLX` / `🟢 DIM.RIA` | Незалежне увімкнення та зупинка кожного парсера | Тільки Адміністратор |
| `🔍 Тест OLX / DIM.RIA` | Миттєвий тестовий прогін (1 коло) із виведенням звіту | Тільки Адміністратор |
| `📦 Об'єкти в базі` | Посторінковий перегляд збережених квартир від власників | Авторизовані (`admin`, `realtor`) |
| `📊 Експорт в Excel` | Генерація `.xlsx` таблиці з усіма оголошеннями | Тільки Адміністратор |
| `👥 Користувачі` | Схвалення заявок, керування ролями та блокування доступу | Тільки Адміністратор |
| `🌐 Меню проксі` | Додавання, перевірка пінгу та видалення проксі-серверів | Тільки Адміністратор |
| `🍪 OLX Cookies` | Перегляд статусу, оновлення та очищення сесійних cookies | Тільки Адміністратор |
| `ℹ️ Системний статус` | Моніторинг стану БД, проксі, підписників та Circuit Breaker | Тільки Адміністратор |
